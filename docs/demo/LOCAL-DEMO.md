# Локальное демо

Демо работает только на компьютере, где запущены приложение и local Supabase. Оно использует вымышленные test credentials из репозитория и не предназначено для публикации.

## Что нужно установить

- Node.js 22;
- Corepack и pnpm версии из поля `packageManager` в `package.json`;
- Docker Desktop или Docker Engine;
- Chromium для полного E2E gate: `pnpm exec playwright install chromium`.

Из корня репозитория активируйте Corepack и установите зависимости:

```text
corepack enable
corepack pnpm install --frozen-lockfile
```

## Подготовка и запуск

```text
pnpm demo:prepare
pnpm demo:verify
pnpm dev
```

`demo:prepare` запускает Supabase из `supabase/config.toml`, делает clean reset, создаёт детерминированный seed и записывает browser-safe local values в `.env.local`. Команда откажется работать, если найденный Supabase URL не loopback или не соответствует порту текущего project config. После подготовки она печатает URL, две локальные роли и следующий шаг.

Откройте `http://localhost:3000/`. Для остановки инфраструктуры используйте `pnpm db:stop`.

`demo:verify` ничего не меняет в бизнес-workflow: он проверяет local endpoint, `.env.local`, вход двух actors, обязательные данные и AREA-изоляцию. При остановленном или нелокальном Supabase команда завершится понятной ошибкой.

## Короткий сценарий

1. Войдите как **генподрядчик · директор по строительству**: `work.manager@construction.test` / `Work-Task015-2026!`. В карточке проекта видны «Демонстрационная организация Альфа · Генподрядчик». В разделе «Работы» доступно создание работы и видны данные всего проекта.
2. Выйдите и войдите как **субподрядчик · мастер/ПТО**: `field@construction.test` / `Field-Task020-2026!`. В карточке проекта видны «Демонстрационная организация Бета · Субподрядчик». Работы проекта доступны для чтения, создание работы недоступно, а создать дневной отчёт можно только в назначенной зоне A.
3. Не изменяйте данные, если хотите повторить исходный маршрут. Для возврата к нему снова выполните `pnpm demo:prepare`.

## Ограничения сети и PWA

`localhost` сам по себе недоступен удалённым участникам и другим устройствам. Нельзя публиковать порты, делать bind на публичный интерфейс, поднимать туннель или раскрывать репозиторные test credentials без отдельного security/hosting решения.

Наличие PWA не означает реализованный offline sync или автономную работу: демо требует запущенных локальных сервисов. Cloud hosting, remote Supabase и публичный доступ в этот сценарий не входят.
