# PWA строительного объекта — декомпозиция предметной области

**Файл:** `docs/product/modules.md`  
**Версия:** 1.1  
**Основание:** ТЗ 1.0 + анализ рабочих документов проекта  
**Статус:** предметная декомпозиция до проектирования БД/API/UI

---

# 1. Цель

Разложить строительное PWA на предметные модули, ключевые сущности и бизнес-процессы.

Главный принцип: **папки и файлы исходных архивов не должны 1:1 превращаться в модули приложения.** Система моделирует реальные строительные процессы и связи между ними.

---

# 2. Базовая структура предметной области

**Организация → Проект → Объект → Захватка / зона → Документация → Работа → Контроль → ИД → КС → Оплата**

Параллельно основной производственной цепочке работают:

- снабжение и ТМЦ;
- персонал;
- ОТ/ТБ;
- геодезия;
- пропуска;
- договоры;
- сметы;
- уведомления;
- задачи;
- согласования;
- история изменений.

---

# 3. Модули системы

## M01. Объекты строительства

Центральный контекст всей системы.

Основные сущности:
- Project;
- объект строительства;
- ProjectArea / захватка / зона;
- конструктив;
- иерархия физических областей.

Связан практически со всеми модулями.

## M02. Участники, роли и зоны ответственности

Определяет, кто участвует в проекте, какую роль выполняет, за что отвечает, что видит и какие действия может выполнять.

Основные сущности:
- User;
- Organization — каноническая организация/компания;
- OrganizationMember — принадлежность пользователя к организации;
- ProjectOrganization — участие организации в конкретном Project с типом (заказчик, генподрядчик, подрядчик, субподрядчик, проектировщик, лаборатория, поставщик и др.);
- ProjectMember — участие User в Project от имени конкретной ProjectOrganization;
- Role;
- Permission;
- ResponsibilityAssignment.

Ключевой принцип: один Project может объединять несколько организаций. Права участника определяются не только Project/Role, но и ProjectOrganization/Scope. Компания не дублируется отдельно как поставщик, субподрядчик и контрагент.

## M03. Проектная и рабочая документация

Основные сущности:
- TechnicalDocument;
- DocumentRevision;
- DocumentFile;
- DocumentIssueForWork;
- DocumentImpact.

Работа связывается с конкретной действующей ревизией, а не просто с PDF.

## M04. Производство работ

Отвечает на вопрос: что сейчас выполняется на площадке.

Основные сущности:
- Work;
- WorkProgressEntry;
- DailyReport;
- Shift;
- Crew;
- ProductionIssue.

DailyReport обновляет состояние существующей Work, а не создаёт отдельную копию работы.

## M05. Планирование и контроль выполнения

Показывает план, факт, сроки, зависимости и блокировки.

Основные сущности:
- WorkDependency;
- WorkRequirement;
- ReadinessRule;
- WorkBlocker;
- QualityGate / ControlPoint.

## M06. Снабжение и ТМЦ

Цепочка: **потребность → заявка → согласование → заказ → поставка → входной контроль → партия → резервирование → выдача → использование.**

Основные сущности:
- Material;
- MaterialRequirement;
- SupplyRequest;
- SupplyRequestItem;
- Delivery;
- MaterialBatch;
- MaterialReservation;
- MaterialMovement;
- MaterialSubstitution.

Владелец процесса — снабженец.

## M07. Строительный контроль и качество

Основные сущности:
- InspectionRequest;
- Inspection;
- QualityChecklist;
- QualityIssue;
- IncomingMaterialInspection.

Владелец — инженер строительного контроля от генподрядчика.

## M08. Исполнительная документация

Основные сущности:
- ExecutivePackage;
- ExecutiveDocument;
- ExecutiveRequirement;
- АОСР;
- исполнительная схема;
- документ качества;
- протокол испытаний.

ИД собирает ссылки на Work, Quality, Material и Documentation, а не создаёт их копии.

## M09. Договоры и контрагенты

Основные сущности:
- Counterparty;
- Contract;
- ContractItem;
- дополнительные соглашения;
- приложения.

Контрагент создаётся один раз и используется договорами, поставками, КС и оплатами.

## M10. Сметы и дополнительные работы

Основные сущности:
- Estimate;
- EstimateItem;
- AdditionalWorkRequest.

Процесс: необходимость → обоснование → объём → стоимость → согласование → договорное основание → Work → выполнение → приёмка → оплата.

## M11. Выполненные работы и КС

Основные сущности:
- ClosingPeriod;
- AcceptedWorkVolume;
- KS2;
- KS3;
- KS6a.

КС не является независимым источником фактического объёма.

## M12. Финансы и оплаты

Основные сущности:
- Invoice;
- PaymentRequest;
- Approval;
- Payment.

Платёж должен иметь бизнес-основание.

## M13. Персонал и учёт рабочего времени

Основные сущности:
- Employee;
- EmployeePosition;
- EmploymentDocument;
- EmployeeProjectAssignment;
- Shift;
- TimesheetEntry;
- Crew.

Один Employee используется в кадрах, ОТ/ТБ, пропусках, отчётах и назначениях на Work.

## M14. Охрана труда и техника безопасности

Основные сущности:
- SafetyQualification;
- SafetyCertificate;
- SafetyBriefing;
- WorkAdmission;
- WorkPermit.

Владелец — инженер по охране труда.

## M15. Пропуска

Основные сущности:
- AccessRequest;
- AccessPass;
- Visitor.

## M16. Геодезия

Основные сущности:
- GeodeticTask;
- GeodeticSurvey;
- GeodeticScheme;
- GeodeticInstrument.

Геодезия может быть обязательной контрольной точкой до начала, во время или после Work.

## M17. Электронные производственные журналы

Основные сущности:
- ElectronicJournal;
- JournalEntry;
- JournalEntryRevision.

Подтверждённые записи нельзя незаметно переписывать или физически удалять.

# 4. Сквозные системные сущности

## Work

Центральная производственная сущность. Используется производством, ежедневными отчётами, качеством, ИД, снабжением, ОТ/ТБ, геодезией, КС и задачами.

## Attachment

Общий механизм прикрепления файлов. Файл не заменяет бизнес-сущность.

## Event

Неизменяемый факт значимого изменения.

## Notification

Доставка информации о Event конкретному пользователю.

## Task

Требуемое действие пользователя. Notification и Task — разные сущности.

## Approval

Общий механизм принятия решения.

## Acknowledgement

Подтверждение ознакомления с критичным изменением.

## AuditEntry

История значимых действий: кто, когда, что изменил, старое/новое состояние и причина.

# 5. Главные связи

## Производственная цепочка

```text
Project
→ ProjectArea
→ TechnicalDocument / Revision
→ Work
→ WorkProgress
→ Inspection
→ ExecutivePackage
→ AcceptedWorkVolume
→ KS
→ Payment
```

## Материальная цепочка

```text
Work
→ MaterialRequirement
→ SupplyRequest
→ Delivery
→ MaterialBatch
→ IncomingMaterialInspection
→ Reservation / Movement
→ Work
→ ExecutivePackage
```

## Кадровая цепочка

```text
Employee
→ EmployeeProjectAssignment
→ SafetyCertificate / Briefing
→ WorkAdmission
→ WorkPermit
→ WorkAssignment
→ Work
```

## Договорная цепочка

```text
Counterparty
→ Contract
→ ContractItem / EstimateItem
→ Work
→ AcceptedWorkVolume
→ KS
→ Payment
```

# 6. Основные бизнес-процессы

- BP-01: создание объекта и назначение участников;
- BP-02: публикация рабочей документации;
- BP-03: изменение рабочей документации и impact analysis;
- BP-04: ежедневное выполнение работ;
- BP-05: заявка на материалы;
- BP-06: поставка и входной контроль;
- BP-07: контроль выполненной работы;
- BP-08: формирование ИД;
- BP-09: дополнительные работы;
- BP-10: закрытие объёмов / КС;
- BP-11: оплата;
- BP-12: добавление сотрудника;
- BP-13: контроль допуска сотрудника;
- BP-14: пропуск;
- BP-15: реакция на значимое событие.

Подробные state machines находятся в `workflows.md`.

# 8. Что не является самостоятельным модулем

- **Шаблоны документов** — библиотека форм.
- **Реестры** — представления доменных данных.
- **Файлы** — вложения/физические версии, а не центр архитектуры.

---

# 9. Центр состояния проекта

Dashboard должен агрегировать из доменных модулей:

- что выполняется;
- что завершено;
- что задерживается;
- что требует действия;
- что заблокировано;
- какие документы изменились;
- какие материалы задерживают производство;
- какие замечания открыты;
- какая ИД некомплектна;
- что готово к КС;
- какие допуски истекают.

Это представление, а не отдельный источник истины.

---

# 10. Границы этапа

На этом этапе зафиксированы предметные модули, ключевые сущности, общие сущности, основные связи и процессы.

Не фиксируются SQL-таблицы, API, структура React-компонентов, физическая реализация RLS и offline engine.
